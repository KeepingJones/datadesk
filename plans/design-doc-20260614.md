## Recommended Approach

**Approach A+ (refined by cross-model review):**

Go public NOW, but make the README do the heavy lifting. The .env cleanup is a PARALLEL
prerequisite — start it first (key rotation takes minutes), then write the README. Do not
push until both are done.

**Step 0 (before writing a word): .env / git history cleanup**
1. Rotate all T212 API keys in the T212 dashboard — make the old keys dead before scrubbing
2. Remove `.env` from git history: `git filter-repo --path .env --invert-paths`
   Note: `git filter-repo` rewrites all commit hashes — any branch references or CI/CD
   integrations pointing to old SHAs will need refreshing (solo project: low risk)
3. Verify no secrets remain: `git log -p | grep -iE "key|secret|token"` — must return nothing
4. Confirm `.env` is in `.gitignore` and will never be committed again
5. Force-push all branches: `git push origin --force --all` (needed because history was rewritten)

**Step 1: Rewrite README lede**
Proposed section order:
1. One-paragraph architecture summary (alt-data pipeline, regime overlay, shadow-first OMS)
2. `## Methodology & Honest Results` — state CAGR with bias-adjusted estimate in the same

   `DEVELOPMENT.md#backtest-realism--bias` for full detail. Do not move or delete section 16.

4. Getting started / commands

**Step 2: Push to public GitHub**

THEN (not before):
